# ZeroTrace Shared Data Contracts & Schemas

ZeroTrace enforces strict, versioned data contracts across all platform components (Person 1 backend, Person 2 scanner integration, Person 3 AI triage and UI reporting). All team members must import and use the canonical data definitions from `aegis_common`.

---

## 1. Canonical Imports

Do **not** define local duplicate classes or Pydantic models. Import directly from the canonical packages:

```python
# Models
from aegis_common.models.assessment import Assessment, ScopeRule
from aegis_common.models.asset import Asset
from aegis_common.models.evidence import Evidence
from aegis_common.models.finding import Finding
from aegis_common.models.job import Job, JobAuditEntry
from aegis_common.models.audit_event import AuditEvent

# Enums
from aegis_common.enums import (
    AssessmentStatus,
    AssetType,
    EvidenceSourceType,
    FindingSeverity,
    ConfidenceLevel,
    VerificationStatus,
    JobStatus,
    ScopeReasonCode,
    ScopeStatus,
    TestPermissionLevel,
)
```

## 2. Core Contract Specifications

### 2.1 Assessment (`Assessment`)
Represents an authorized security engagement.
- `id` / `assessment_id` (str): Unique UUID/slug identifying the assessment.
- `name` (str): Human-readable name.
- `authorization_reference` (str): Formal authorization ticket, contract, or permit number.
- `authorization_acknowledged` (bool): Must be `True` to allow approval and scanning.
- `scope_rules` (ScopeRule): Defines `included_targets` and `excluded_targets`.
- `status` (AssessmentStatus): `DRAFT`, `PENDING_APPROVAL`, `APPROVED`, `ACTIVE`, `COMPLETED`, `CANCELLED`.
- `permitted_test_profiles` (List[TestPermissionLevel]): List of allowed actions (e.g., `PASSIVE_RECON`, `NETWORK_SCAN`).

### 2.2 Asset (`Asset`)
Represents an identified network or host target.
- `id` / `asset_id` (str): Unique identifier.
- `assessment_id` (str): Owning assessment ID.
- `target_value` / `hostname_or_address` (str): Canonical hostname, IP, or URL.
- `asset_type` (AssetType): `DOMAIN`, `SUBDOMAIN`, `IP_ADDRESS`, `CIDR_BLOCK`, `URL`.
- `scope_status` (ScopeStatus): `IN_SCOPE`, `OUT_OF_SCOPE`, `EXCLUDED`.
- `first_seen` / `last_seen` (datetime): Temporal tracking.

### 2.3 Evidence (`Evidence`)
Represents empirical observation data gathered by an adapter or scanner.
- `id` / `evidence_id` (str): Unique identifier.
- `assessment_id` (str): Owning assessment ID.
- `asset_id` (Optional[str]): Target asset ID.
- `source_type` (EvidenceSourceType): `OSINT`, `DNS`, `HTTP`, `PORT_SCAN`, `WEB_VULN_SCAN`, etc.
- `content_hash` (str): SHA-256 hex digest of the raw payload.
- `raw_payload` / `raw_data` (Any): Sanitized excerpt or raw observation.
- `collected_at` (datetime): Timestamp of collection.

### 2.4 Finding (`Finding`)
Represents an identified vulnerability or security exposure.
- `id` / `finding_id` (str): Unique identifier.
- `assessment_id` (str): Owning assessment ID.
- `asset_id` (Optional[str]): Affected asset ID.
- `title` (str): Concise vulnerability title.
- `severity` (FindingSeverity): `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFORMATIONAL`.
- `confidence` (ConfidenceLevel): `CONFIRMED`, `HIGH`, `MEDIUM`, `LOW`.
- `verification_status` (VerificationStatus): `CONFIRMED`, `LIKELY`, `UNVERIFIED`.
- `evidence_references` (List[str]): List of valid `evidence_id` strings proving the finding.
  - **Rule**: A finding cannot have `verification_status == CONFIRMED` if `evidence_references` is empty.
- `remediation` (Optional[str]): Remediation steps.

### 2.5 Job (`Job`)
Represents an asynchronous or scheduled backend task.
- `id` / `job_id` (str): Unique identifier.
- `assessment_id` (str): Associated assessment ID.
- `task_type` (str): E.g., `osint_recon`, `port_scan`, `report_generation`.
- `status` (JobStatus): `CREATED`, `POLICY_CHECK`, `QUEUED`, `RUNNING`, `REVIEW`, `NEEDS_APPROVAL`, `COMPLETED`, `FAILED`, `CANCELLED`.
- `parameters` (dict): Task-specific execution arguments.

## 3. Schema Versioning & Evolution Rules

1. **Frozen v1 Contracts**:
   - The schemas located in `schemas/v1/` and `aegis_common/models/` represent Version 1.0.
   - Breaking field removals or renames in Version 1.0 are strictly prohibited.
2. **Backward Compatibility**:
   - New fields added to contracts **must** have default values or be marked `Optional`.
   - String enums must support case-insensitive serialization/deserialization.
3. **No Unbacked Claims**:
   - Findings submitted by Person 2 scanners or generated by Person 3 AI models must cite verifiable `evidence_id` values stored in the evidence repository.
   - Any finding with missing evidence references is clamped to `UNVERIFIED`.
4. **Validation Integrity**:
   - Any external JSON schema generator or consumer should validate against `schemas/v1/` JSON schemas.
